# Linux (GTK 4)

> **Preview in 0.1:** it works and can be tried, but has gaps (listed on this page) and is less tested on real devices than web, macOS, iOS and Android. See [Platforms in 0.1](../introduction.md#platforms-in-01).

`cargo run` on Linux opens a native GTK 4 window: `GtkLabel`, `GtkButton`, `GtkEntry`, `GtkSwitch`, `GtkProgressBar`, `GtkPicture` and `GtkScrolledWindow`. Navigation stacks get a header with a Back button, tabs a tab bar, and modals their own window.

- Layout is prism-native's flexbox: a small GTK layout manager puts each widget at its frame, so screens look like on macOS. Styles become generated CSS.
- Wrapping labels report their longest word as minimum width.
- Storage goes to `$XDG_DATA_HOME/<title>`; the language comes from `LANG`. `cx.device_info()` reports the distribution's `VERSION_ID` and the monitor (size in mm, refresh rate).
- Develop and test in Docker: `docker build -f docker/linux-dev.Dockerfile -t prism-linux-dev docker`, then run the app under `xvfb-run` with `PRISM_SNAPSHOT`/`PRISM_CLICK` (see CI).
- Accessibility uses GTK's C API (`gtk_accessible_update_property_value` and the like, available in every GTK 4); gtk-rs only binds it from 4.10. A drawn control (a clickable view, a custom check box or tab) gets its role, takes the focus with Tab and is pressed with Enter or Space, as on the web; Tab also reaches a view with `on_key_down` and a clickable text. The tab bar is a tab list. GTK 4.8 and 4.9 name an element without a label after its type (`PrismBox`), and 4.10 and 4.11 leave it unnamed: on those versions Prism names rows, cells, buttons and tabs after their content, as GTK 4.12 and later do, and gives other elements an empty name. `scripts/linux-a11y.sh` dumps and checks the AT-SPI tree Orca gets, on GTK 4.8 and on the newest GTK (`docker/linux-a11y.Dockerfile`). Tables: see [Tables](../guide/tables.md#screen-readers).
- Location uses GeoClue2 over the system bus, asynchronously; `request_permission` starts a client, so the desktop's agent asks the user. Also available: the file chooser for photos, the clipboard, opening links with the default app.
- Notifications use `GNotification`, with buttons; the dev image's D-Bus monitor shows them. Alerts are modal windows. Context menus open on right-click or press and hold (`GtkPopoverMenu`). `set_app_menu` becomes the menu bar, with shortcuts.
- The tray is a StatusNotifierItem with its menu over `com.canonical.dbusmenu` (KDE Plasma, GNOME with the AppIndicator extension, most panels), served by Prism itself over GDBus on a thread of its own; a click on the icon brings the window forward, and a tray set before the panel starts shows up when it does. `scripts/linux-tray-smoke.sh` checks it in the dev image against a stand-in watcher (`scripts/mock-sni-watcher.py`). Also supported: swipes (touchpad), scroll events, refresh with F5 / Ctrl+R, lifecycle (focus, minimized) and background tasks while the app runs. Text size follows GNOME's scaling factor; reduced motion follows "animations off".
- Rich inputs are `GtkTextView`s: the runs are text tags, each chip or icon a widget at a child anchor that counts as one character; pastes hand the app the clipboard's text, HTML and the text of its other types ([Rich text input](../guide/forms.md#rich-text-input)).
- Secrets use the Secret Service (D-Bus; `biometric` ones answer `Unavailable`, since no Linux store ties a secret to the user's presence), fingerprints fprintd, sign-in the default browser with a loopback redirect (see [Security](../guide/security.md)).
- No desktop standard exists for motion, camera, haptics or a share sheet, so `capabilities` reports them as unavailable.
- No [web views](../guide/web-views.md) yet (WebKitGTK would add a system dependency): `web_view` draws an empty box and `capabilities().web_view` is false.
